# 数字彩研究运行与判定

目标：在相同成本下寻找可重复的收益优势。当前入口为 `index.html`，原组合工具迁移至 `number-tools.html`；离线版本分别为 `lotto-standalone.html` 与 `number-tools-standalone.html`。足球协议独立保存，不因数字彩重构重新开始。

## 实际执行

```powershell
npm run numbers:daily       # 公共数据采集、逐期回测、开奖前登记、开奖后结算
npm run numbers:daily -- --cached --preview # 只读已有公开输入做预览，不登记预测
npm run numbers:evaluate    # 独立生成可复现历史报告
npm run build              # 更新全部独立页面
npm run verify             # 离线确定性验收
npm run serve              # http://127.0.0.1:8080/index.html
```

每日任务退出码：0 正常，2 数据来源降级，1 执行错误。失败保留此前有效开奖记录；下一期预告取不到时关闭新登记，不猜期号。每日在北京时间 10:30、18:30、23:30 与原足球任务顺序运行；电脑和 Codex 必须可运行，调度器未执行的时段不补造预测。

## 数据和规则

- `data/numbers/sources.json` 保存来源字段；`raw/` 保存原始响应及 SHA-256。双色球源为公开历史和逐期奖表，大乐透逐期奖金优先广东体彩官方公告；下一期预告为次级公开来源，页面明确其身份。官方销售截止没有取得时保留空值。
- `number-rule-context.js` 按官方第十八条、期号和连续的上期奖池推导双色球福运奖状态。原始数据不修改；派生状态保留规则与公告证据，缺期或矛盾回到未知，绝不补造奖金。
- `number-settlement.js` 按期号选择规则，分别核算基本、追加、福运与未验证资格的派奖。未中奖可确定为零；未知中奖奖金不能按零核算。浮动奖“0 注、0 元”不意味着新增一名中奖者奖金为零。
- 报告为公告奖表下的税前纸面核算，没有模拟新增中奖者后重新分配奖池，也没有真实下注。号码概率、条件分奖、活动资格和净收益是不同问题。

## 模型与公平比较

固定候选：均匀随机、频率收缩、近期收缩、遗漏反转、转移收缩、完整组合混合、票组覆盖。概率模型采用完整子集分布 `P(S)=乘积权重/e_k(权重)`；概率计算与采样使用同一归一化分布，避免“打分说一种概率，实际抽样却是另一种分布”。混合模型在完整票空间混合；覆盖优化不宣称提高公平抽奖下的期望返奖。

历史评估最少 200 期训练，当前输入末 120 期测试，每模型每期 5 注、10 元，逐期只使用此前号码。保存输入哈希和完整票组，不根据测试结果挑选种子或删除失败模型。当前采集的历史只能称回溯重建，不能成为开奖前实绩。

## 前瞻协议与更正

第一次真实登记冻结 `data/numbers/protocol.json` 的代码、预算、比较族、固定窗口和完整收据哈希。每彩种每期所有模型原子登记，预测前来源必须已观察并核对原文哈希。训练截止 `forecastAsOf` 与生成完毕的 `registeredAt` 分开；生成和写盘跨过研究截止都拒绝发布。截止为预告开奖前 3 小时，若取得更早真实销售截止则服从后者。

同一期重跑只读原票组，绝不重新抽签。更正或撤回追加新的结算版本，汇总只取截至指定时刻的最新版本，不重复累计。365 日窗口结束后停止该协议新登记，已有批次继续结算，最低每彩种 120 期不自动等于成功。协议变更需要新研究批次，不能改旧实验来获得好结果。

## 什么才算证据

1. **号码分布**：固定可预测模型相对均匀独立开奖假设累积似然比。两彩种 12 个候选比较的阈值为 `12/0.05=240`。已到期但缺少号码评分时暂停判断；中奖金额待核但号码确定时仍可评分。历史 e 值仅为诊断。
2. **相对收益**：同一期、同预算与随机票组配对，完整窗口报告净额和差额。遗漏任一期奖金时，完整窗口差额保持未知，不能用剩余小计替代。
3. **可靠盈利**：分布异常、覆盖更多、回测少亏或短期盈利均不够。还需固定前瞻窗口的结果、适用奖池分配与活动资格，以及能处理罕见高奖尾部的收益不确定性界。当前缺少这项证明，不启用自动“盈利方案”晋级。

公平独立开奖下，任意开奖前固定的合法单注头奖概率相同；同预算改变形态本身不会提升期望奖表返奖。因此本实现将分布偏差作为可证伪假设检验。后续若研究人群分奖、销售与奖池择时，必须先取得相应真实输入和规则，另立候选协议，不能用旧人工“反人群分”充当实测收益优势。

## 回退与核对

主界面迁移可回看独立保留的旧工具；新旧引擎不混合调用。冻结协议或计算代码不一致时停止新增登记和结算，保留原始文件与收据，查看具体哈希差异并恢复原版本或建立新协议。不得删除活进程锁，不得回填错过的开奖前时间。工程验收结论为 `READY_FOR_JUDGMENT`；收益优势是否成立由证据判定。
